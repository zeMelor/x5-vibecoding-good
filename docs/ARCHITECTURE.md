# Выручаем.AI — Фудшеринг-Диспетчер (Архитектура и алгоритмы)

> Интеллектуальная система координации фудшеринга для экосистемы **X5 Tech + «X5 Клуб» + благотворительный фонд «Выручаем»**.

---

## 1. Проблема и ценность

Каждый вечер в магазинах («Пятёрочка», «Перекрёсток») и дарксторах X5 появляются партии пригодных к употреблению продуктов с подходящим сроком годности (хлебобулочные изделия, овощи, фрукты, бакалея). Сейчас координация волонтёров во многом идёт вручную через чаты:
- часть продуктов не успевает доехать до адресатов в пределах окна годности (`TTL`);
- наборы формируются «на глаз» — без учёта состава семьи, диетических ограничений и баланса рациона;
- маршруты волонтёров не оптимальны, а сами волонтёры быстро выгорают без прозрачной обратной связи и мотивации.

**Выручаем.AI** закрывает весь цикл спасения еды за 60 секунд и связывает все 3 контура организаторов:
1. **X5 Tech** — AI-комплектация, алгоритмическая маршрутизация, валидация регламентов, чистый веб-интерфейс.
2. **Фонд «Выручаем»** — адресная помощь семьям/пенсионерам, рост охвата (+10%/год KPI), прозрачная ESG-отчётность.
3. **«X5 Клуб»** — начисление баллов лояльности и «Чек добра» волонтёрам за каждый спасённый рейс.

---

## 2. Ключевые модули MVP (4 роли в одном интерфейсе)

### 2.1. Роль «Магазин / Даркстор»
- **Быстрый ввод партии:** свободный текст / голосовой ввод / вставка накладной / 1-клик демо-пресеты (например: *«Пятёрочка #412: 12 батонов до 22:00, 8 кг яблок, 6 пачек гречки, 5 упаковок творога»*).
- **AI-парсер + валидатор регламента X5:**
  - Извлекает структурированные позиции (название, категория, количество, вес, `TTL` в часах, теги аллергенов).
  - **Фильтр безопасности фудшеринга:** автоматически помечает и отсеивает недопустимые позиции (просрочка `TTL <= 0`, сырое мясо/рыба, алкоголь, повреждённая упаковка) с объяснением причины.

### 2.2. Роль «AI-Диспетчер» (главный экран)
- **Интерактивная карта (Leaflet):**
  - Точки магазинов с бейджами срочности (красный: `< 3 ч`, жёлтый: `3–8 ч`, зелёный: `> 8 ч`).
  - Точки семей-получателей (обезличенные зоны/кварталы для приватности).
  - Точки доступных волонтёров (пешие / авто) и проложенные маршруты.
- **Кнопка «Запустить AI-распределение»:**
  - Запускает пайплайн: *Комплектация корзин → Назначение волонтёров → Оптимизация маршрутов → AI-объяснение решений*.
  - Показывает сравнение **«До (ручной разбор) vs После (Выручаем.AI)»**: % спасённой еды, сокращение времени доставки, охват семей.

### 2.3. Роль «Волонтёр + X5 Клуб» (мобильный вид)
- Карточка активного рейса: откуда забрать (код/чек-лист), куда доставить (пошаговый маршрут), таймер свежести.
- Симуляция пуш-уведомлений о срочных партиях рядом.
- **«Чек добра»** (отсылка к виджету `/чек` от X5 Tech): по завершении рейса генерируется стилизованный кассовый чек — спасённые кг, эквивалент в «пачках гречки», сэкономленный CO₂ и **начисленные баллы «X5 Клуба»**.

### 2.4. Роль «Фонд Выручаем / Аналитика»
- KPI-дашборд: спасённая еда (кг), накормленные семьи, сэкономленный CO₂ (`1 кг еды ≈ 2.5 кг CO₂`), снижение утилизации (₽).
- Экспорт отчёта (JSON / CSV) и журнал решений AI.

## 3. Алгоритмическое ядро (реальная математика + LLM)

Система работает **гибридно**: детерминированные алгоритмы гарантируют корректность, скорость и соблюдение ограничений (даже без API-ключа), а LLM-слой (OpenAI / Anthropic / OpenRouter с локальным fallback) отвечает за парсинг свободного текста, семантическую проверку регламентов и человеческие пояснения.

### Алгоритм 1: Умная комплектация корзин (Constrained Multi-Objective Packing)

**Вход:**
- Партии товаров $I = \{i_1, \dots, i_n\}$: вес $w_i$, категория $c_i \in \{\text{хлеб}, \text{овощи/фрукты}, \text{бакалея}, \text{молочка}, \text{выпечка}\}$, остаток срока $TTL_i$ (часы), теги ограничений $T_i$ (сахар, лактоза, глютен, орехи).
- Профили семей $F = \{f_1, \dots, f_m\}$: число человек $s_f$, наличие детей, диетические запреты $D_f$, дней с последней помощи $d_f$, целевой вес корзины $W_f^{\max} \approx 2.5 \cdot s_f$ кг, координаты $(lat_f, lon_f)$.

**Жёсткие ограничения (Hard Constraints):**
1. $T_i \cap D_f = \emptyset$ (ноль аллергенов/противопоказаний: диабетику не кладём сладкую выпечку и т.п.).
2. Если $TTL_i < 4$ ч, семья должна находиться в пределах быстрого плеча доставки ($\le 3$ км от магазина).
3. Лимит одной категории в корзине: не более 40% веса из одной категории (чтобы не отдавать 8 кг одного хлеба).

**Функция приоритета (Scoring) для пары (товар $i$, семья $f$):**
$$\text{Score}(i, f) = \alpha \cdot \underbrace{\frac{1}{\max(TTL_i, 1)}}_{\text{срочность}} + \beta \cdot \underbrace{\min\left(\frac{d_f}{14}, 1\right)}_{\text{справедливость}} + \gamma \cdot \underbrace{\text{DiversityBonus}(c_i, B_f)}_{\text{баланс рациона}} - \delta \cdot \underbrace{\text{Dist}(store_i, f)}_{\text{плечо}}$$

- `DiversityBonus` даёт +1.0, если категории $c_i$ ещё нет в текущей корзине $B_f$, и +0.2, если уже есть.
- **Результат:** сбалансированные, безопасные продуктовые наборы с максимальным процентом спасения скоропорта.

### Алгоритм 2: Маршрутизация волонтёров (Capacitated VRP + 2-opt)

**Вход:**
- Собранные корзины $B_f$ с привязкой к магазину забора и весом $W(B_f)$.
- Волонтёры $V = \{v_1, \dots, v_k\}$: координаты, тип транспорта (`пеший`: 8 кг / 4.5 км/ч; `вело`: 15 кг / 14 км/ч; `авто`: 45 кг / 28 км/ч), доступное время $T_v^{\max}$.

**Шаги:**
1. **Кластеризация по магазинам и срочности:** корзины группируются по магазину забора и сортируются по минимальному $TTL$ внутри корзины.
2. **Жадное назначение (Urgency-First Assignment):** для самой срочной группы подбирается ближайший свободный волонтёр, у которого хватает грузоподъёмности и временного окна.
3. **Оптимизация обхода (2-opt Local Search):** для каждого волонтёра порядок посещения семей оптимизируется алгоритмом `2-opt` по Haversine-дистанции с приоритетом на корзины с минимальным $TTL$.
4. **Бенчмарк «До / После»:** параллельно считается базовый «наивный» маршрут (без оптимизации), чтобы на UI показать реальную экономию минут и километров.

### Алгоритм 3: Расчёт импакта и баллов «X5 Клуба»
- **Сэкономленный CO₂:** $\text{CO}_2 = \sum w_i \cdot k_{c_i}$ (хлеб/бакалея ~1.5 кг CO₂/кг, овощи/фрукты ~2.0, молочка ~3.5; в среднем ~2.5 кг CO₂ на 1 кг спасённой еды).
- **Эквивалент «пачек гречки»:** $1 \text{ пачка} = 0.8 \text{ кг}$ базового рациона (красивая визуальная связка с виджетом X5 Tech).
- **Баллы «X5 Клуба» волонтёру:** `base(50) + 15 * спасённые_кг + бонус_за_срочность(TTL < 4ч ? 50 : 0)`.

## 4. Технический стек (быстро, чисто, запускается без ключей)

- **Frontend:** React 18 + TypeScript + Vite + Tailwind CSS
- **Карта:** Leaflet (`react-leaflet` / `leaflet` с OpenStreetMap тайлами — бесплатно и без API-ключей)
- **Иконки и графики:** `lucide-react` + лёгкие SVG-индикаторы / `recharts`
- **AI-слой:** `src/services/ai.ts` — поддержка OpenAI-совместимого API через `VITE_LLM_API_KEY` + полноценный умный локальный fallback (парсер накладных + генератор объяснений), чтобы проект идеально работал из коробки у любого члена жюри.
- **Структура проекта:**
  ```text
  src/
    data/          # Реалистичные моки магазинов X5, семей и волонтёров
    algorithms/    # packing.ts (комплектация), routing.ts (VRP + 2-opt), impact.ts
    services/      # ai.ts (парсер накладных + объяснения + fallback)
    components/    # MapView, StorePanel, DispatcherPanel, VolunteerMobile, ImpactDashboard, GoodReceiptModal
    types/         # Строгие TS-типы
  ```

## 5. План разработки («делаем грязюку»)

1. **Этап 1 — Каркас + Алгоритмы:** инициализация Vite/React/TS/Tailwind, типы, мок-данные, чистые модули `packing.ts`, `routing.ts`, `impact.ts` + юнит-тесты алгоритмов.
2. **Этап 2 — UI и Карта:** карта Leaflet с магазинами/семьями/маршрутами, переключатель 4 ролей, стиль в фирменной палитре X5 (зелёный + чистый светлый/тёмный UI).
3. **Этап 3 — AI-парсер накладных и «Чек добра»:** ввод свободного текста из магазина, валидация регламентов фудшеринга, генерация красивого «Чека добра» с баллами «X5 Клуба» и экспорт отчёта.
4. **Этап 4 — Полировка и сдача:** демо-сценарий в 1 клик, скриншоты, финальный `/чек` из виджета Claude Code, обновление `README.md` и пост в комменты на Хабр до 7 декабря.
